# TrustChain — Self-Sovereign Identity KYC Platform

A production-ready prototype of a decentralized, privacy-first KYC system for financial institutions using WebAuthn biometrics, W3C DIDs, and EVM smart contracts.

## SSI Model

Self-Sovereign Identity means the user — not any company — controls their identity.

| Traditional KYC | SSI KYC (TrustChain) |
|---|---|
| Bank stores passport scan | Passport verified off-chain; hash only |
| Bank stores selfie / face embedding | No biometric data stored anywhere |
| Identity tied to one institution | Portable across all institutions |
| User asks bank to delete data | User revokes their own DID |
| Central honeypot for attackers | No central identity store to breach |

### DID Method: `did:webauthn`

```
did:webauthn:<base64url(credentialId)>

Example:
did:webauthn:ZoRSLdO-mTzFm7mvmyXJ8M4HklimBJLg4sGGNv_kSyk
```

- The DID is derived from the WebAuthn credential ID
- The credential ID is randomly generated by the device during registration
- The DID Document maps to a verification method backed by the ES256 public key

## WebAuthn Flow

### Registration

```
1. User opens TrustChain, enters email
2. navigator.credentials.create({ publicKey: ... }) called
3. Device prompts for biometric (Touch ID / Face ID / PIN)
4. Device generates ES256 key pair in Secure Enclave
5. Public key + credential ID returned to browser
6. DID derived from credential ID: did:webauthn:<credId>
7. Public key anchored to blockchain via SSIRegistry.registerDID()
8. Only public key hash stored on-chain
```

### Authentication

```
1. Institution generates random 32-byte challenge via /api/auth/challenge
2. navigator.credentials.get({ publicKey: ... }) called
3. Device prompts for biometric
4. Private key (never exported) signs: authData || SHA256(clientDataJSON)
5. Signature sent to /api/auth/verify
6. Server fetches public key from blockchain
7. Server verifies ECDSA P-256 signature using Web Crypto / Node crypto
8. On success: SSIRegistry.recordVerification() called on-chain
9. KYC level updated; Verifiable Credential issued
```

## Security Mechanisms

### 1. Biometric Security
- Biometric templates remain in device Secure Enclave (Apple T2/M-chip, Android StrongBox)
- WebAuthn/FIDO2 specification guarantees: biometric never transmitted
- Even if TrustChain server is compromised: no biometric data to steal

### 2. Cryptographic Security
- ES256 (ECDSA P-256): 128-bit security level
- Private key hardware-bound; cannot be exported even by malware
- Challenge-response prevents replay attacks
- Used challenges stored on-chain (immutable replay log)

### 3. Blockchain Security
- Smart contract is immutable once deployed
- DID → public key mapping is permanent and auditable
- No single point of failure (decentralized)
- KYC history is non-repudiable

### 4. Privacy by Design
- Zero raw biometric data transmitted or stored
- Public key hash (not the key itself) serves as identifier
- DIDs are pseudonymous (no PII embedded)
- Users can generate new DID (key rotation) without losing identity

## Privacy Guarantees

| Data | Stored Where | Who Can See |
|---|---|---|
| Biometric template | Device secure enclave ONLY | Nobody (hardware isolated) |
| Private key | Device secure enclave ONLY | Nobody (hardware isolated) |
| Public key (bytes) | On-chain (blockchain) | Anyone (public) |
| Public key hash | On-chain | Anyone (public) |
| DID | On-chain + locally | Anyone (by design) |
| KYC level | On-chain | Authorized institutions |
| Credential metadata | On-chain | Authorized institutions |
| IP address | NOT stored | N/A |
| Username/email | Locally in browser only | User only |

## Smart Contract: SSIRegistry

Deployed on Polygon Amoy testnet.

### Key Functions

```solidity
// Register a new DID with public key
function registerDID(string did, bytes publicKey) external

// Record a KYC verification (institution only)
function recordVerification(string did, bytes32 challenge, uint8 kycLevel) external

// Issue a Verifiable Credential
function issueCredential(string did, string credentialType, uint256 expiresAt, bytes32 hash) external

// Check KYC compliance
function isKYCValid(string did, uint8 requiredLevel) external view returns (bool)
```

### KYC Levels
- Level 0: Unverified
- Level 1: Basic KYC (name, email, ID number)
- Level 2: Enhanced KYC (address, source of funds)
- Level 3: Full Compliance (PEP/AML checks, video verification)

## Deployment

### Prerequisites
- Node.js 18+
- MetaMask with Polygon Amoy testnet MATIC (from faucet.polygon.technology)

### 1. Deploy Smart Contract

```bash
cd hardhat
npm install
cp .env.example .env
# Edit .env: add PRIVATE_KEY and POLYGON_AMOY_RPC
npm run deploy:amoy
# Copy output contract address
```

### 2. Run Backend

```bash
cd server
npm install
CONTRACT_ADDRESS=0x... INSTITUTION_PRIVATE_KEY=0x... node index.js
# Runs on http://localhost:3001
```

### 3. Run Frontend

```bash
npm install
VITE_CONTRACT_AMOY=0x... npm run dev
# Runs on http://localhost:5173
```

> **Note:** WebAuthn requires HTTPS in production. For localhost development it works over HTTP. Use ngrok or Cloudflare Tunnel for mobile testing.

## Advanced Enhancements (Roadmap)

### Zero-Knowledge Proofs
Use a ZK circuit (e.g. Groth16 via snarkjs) to prove:
- "I am over 18" without revealing date of birth
- "My KYC level ≥ 2" without revealing which institution verified me
- "I am not on a sanctions list" without transmitting my name

### Verifiable Credentials (W3C VC)
Full W3C VC Data Model v2.0 implementation:
- JSON-LD signed credentials
- Selective disclosure (holder presents only required claims)
- Cross-institution credential portability

### Cross-Bank Reusable KYC
DID-based federated KYC: complete KYC once, reuse across all participating institutions via:
- Credential presentation protocol (OpenID4VP)
- Selective disclosure JWT (SD-JWT)
- Institution verification of credential signature

### EEG-Based Biometric (Experimental)
- EEG signals as a continuous authentication factor
- Integrates with consumer EEG headsets (Emotiv, Muse)
- Provides liveness detection against replay attacks
- Raw EEG never transmitted — only frequency-domain features computed locally
